## [Не выпущено]

### Исправлено
- Проверка пакетов плагинов строже: до 600 записей в архиве, без повторяющихся путей (без учёта регистра) и путей, где файл служит папкой; размер проверяется до чтения подписи. При обновлении плагина его папка `data` больше не вкладывается сама в себя (из PR sorried, losted-dev/lostos-server#2)
- На общем сервере (`LOSTOS_MODE=tenant`) работают только плагины, подписанные командой lostOS: код остальных пока не изолирован от других домов. Их можно установить, но не включить, и панель говорит почему (там же)
- `.gitattributes` не даёт git на Windows менять концы строк в манифестах встроенных плагинов: иначе их подпись не сходится (там же)
- Колонка, у которой слово активации срабатывает с опозданием (Станция 1: уже после «Алиса, привет»), больше не молчит: если после сигнала ничего не сказали, просьба берётся из того, что прозвучало сразу после «Алисы»
- Плагины больше не получают окружение сервера целиком: туда хранилище кладёт ключи владельца (Gemini, Home Assistant и другие), и любой плагин мог их прочитать. Теперь у плагина только системные переменные (PATH, временная папка, язык, прокси, сертификаты).
- Голос из плагина (например, «Голос Microsoft») пропадал из списка голосов, если процесс плагина не запустился. Теперь он остаётся в списке с причиной («Плагин не запущен: …»), а сервер запоминает последнюю строку ошибки плагина и показывает её на его странице.
- «Голос Microsoft» 1.0.1: без пакетов edge-tts и soundfile плагин не падает, а отвечает понятной ошибкой с командой установки.
- Подписанный доверенным разработчиком плагин помечался «разработчик не подтверждён»: метка учитывала только встроенные плагины.
- Строка разрешения на странице плагина: текст уезжал в середину строки.
- Установка или удаление одного плагина «теряли» остальные запущенные: их процесс продолжал работать без связи с сервером, страница показывала «не запущен», команды ассистенту пропадали. Теперь запущенные плагины переживают пересканирование папки.
- Админка («Память сейчас») и мягкий лимит памяти считали RSS процесса дома: туда целиком входят общие библиотеки зиготы, поэтому экономия не была видна (85 МБ вместо реальных 37), а плагины не считались вовсе. Теперь это собственная память дома вместе с его плагинами, как её считает ядро в cgroup дома (`memory.current` без файлового кэша); без cgroup — Pss процесса. Поле статуса `rss_mb` переименовано в `mem_mb`.
- Дома, порождённые `zygote.py`, получали SIGPIPE по умолчанию (смерть процесса при записи в закрытое соединение), а не как обычный Python (ошибка `BrokenPipeError`). Теперь сигналы как у свежего Python.

### Добавлено
- Выбор слова активации в панели: LLM → «Алиса» → «Слово активации» (Алиса, Яндекс, Yasmina — какие есть на колонке). Раньше слово переключалось только из Home Assistant. Сервер читает и задаёт его по ESPHome API (`get/set_voice_assistant_configuration`), эндпоинт `/api/v1/wake`.
- Имя ассистента следует за словом активации колонки: «Yasmina» — ассистент зовётся Yasmina и отвечает от этого имени, «Яндекс» имя не меняет (остаётся «Алиса»). Слово приходит с колонки при каждом обращении; правится только начало системного промпта, текст персоны трогать не нужно.
- Общий сервер: дома порождаются через `fork` от одного родителя, который один раз загружает библиотеки (`zygote.py`). Собственная память дома 56 → 26 МБ, PSS 60 → 33 МБ (замер `tests_memory.py`, 5 домов, Linux). `LOSTOS_ZYGOTE=0` возвращает старый способ; если родитель недоступен, дом запускается по-старому сам.
- Серверные плагины домов тоже порождаются от `zygote.py` (unix-сокет `zygote.sock` в папке данных, каналы передаются через SCM_RIGHTS). Плагин попадает в cgroup своего дома и получает только окружение плагинов. «Голос Microsoft»: собственная память 32 → 5 МБ на дом; 3 дома с двумя плагинами: PSS всех процессов 333 → 211 МБ (`tests_memory.py 3 20 ru.lostos.edge-voice,ru.lostos.music-stats`). Маленьким плагинам выгоды почти нет (5 МБ и было). Без зиготы плагин запускается обычным Python. Тест `tests_zygote.py`.
- Плагины на JavaScript, которые работают на колонке (`docs/plugins-js.md`): серверу не нужен их процесс, их команды ассистента приходят с колонки (`plugins_state`) и выполняются там же (`plugin call`). Манифест: `"side": "speaker"`, `"device": {"runtime": "js", …}`, `entry` не нужен. Новое разрешение колонки `assistant.tools`.
- Плагин «Интернет-радио» (`ru.lostos.radio`): первый плагин на JavaScript, каталог radio-browser.info.
- Первая настройка предлагает «Свой сервис» (любой OpenAI-совместимый API): адрес, модель и ключ прямо в мастере.
- Шаг Spotify в первой настройке показывает, работает ли на колонке приёмник Spotify Connect.

## [0.1.0] — 2026-10-25
Первая версия под именем lostOS.

### Добавлено
- Панель lostOS (PWA, iOS-26 Liquid Glass): телефон и ПК, HTTPS со своим сертификатом, web-push уведомления.
- Будильники как в iOS, таймеры, напоминания, сценарии (голос, расписание), таймер сна, умный дом (Home Assistant).
- Движки распознавания и озвучки: облако Алисы по умолчанию, Whisper и Silero по желанию.
- Обложка из потока AirPlay, лайк только для Spotify, громкость Spotify/Bluetooth связана с главной.
- Звук громкости с выключателем, проверка состояния служб, резервная копия.

### Исправлено
- Отсчёт до будильника в панели обновляется каждую секунду.
- Сценарии со словами, которые облако маскирует звёздочками.
