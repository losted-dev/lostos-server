# lostOS: единый API, медиа и плагины (проект, этап C)

Статус: проект на согласование. Кода по нему пока нет, кроме уже работающих кусочков (см. раздел 6).

## 1. Слои

```
 телефон / ПК (панель, PWA) ─┐
 Home Assistant ─────────────┤   lostOS API v1 (REST + WebSocket)
 плагины (процессы) ─────────┤
                             ▼
                     lostOS Server (ПК, позже хостинг)
                     мозг, голос, сценарии, плагины, панель
                             │  ESPHome API (Noise) — транспорт к колонке
                             ▼
                     lostOS Firmware (колонка)
                     кнопки, экран, кольцо, звук, источники музыки
```

Принцип: **что должно работать без сервера, живёт в прошивке** (будильники, громкость, музыка, медиа-арбитраж). Всё остальное — сервер и плагины.

## 2. lostOS API v1 (сервер)

Один вход: `/api/v1`, токен в куки (панель) или `Authorization: Bearer` (плагины, Home Assistant). События — WebSocket `/api/v1/events`.

| Раздел | Что | Сейчас |
|---|---|---|
| `media` | состояние, команды play/pause/next/prev/seek/volume, список источников | разбросано: AirPlay, Spotify, Bluetooth по отдельности |
| `device` | громкость, кольцо, часы, экран, кнопки (события) | ESPHome-сервисы колонки |
| `voice` | `say`, `listen`, запуск интента, смена движков | tool-ы Gemini и `/api/do` |
| `scripts` | сценарии: список, запуск, правка, расписание | `scenarios.json`, `/api/do sc_*` |
| `alarms`, `timers`, `reminders` | CRUD и события срабатывания | `reminders.py`, `/api/do` |
| `home` | умный дом (Home Assistant), сцены | `homeassistant.py` |
| `plugins` | установка, разрешения, включение, обновления | нет |
| `system` | версия, обновления, здоровье, резервные копии | `/api/health`, `/api/backup`, `update.py` |

Правило: панель, Home Assistant и плагины ходят только в этот API. `/api/state` и `/api/do` остаются как совместимость и постепенно превращаются в тонкие обёртки.

## 3. media-play — один скрипт на все источники

Сегодня AirPlay, Spotify и Bluetooth управляются в трёх местах: `airplay.sh`, `bt.sh`, сокет librespot, ветвления в `Controller::transport`, `music_control` на сервере.

Цель: **MediaHub** с одним интерфейсом источника.

```
MediaSource:
  id: "airplay" | "spotify" | "bluetooth" | "dlna" | <плагин>
  capabilities: { play, pause, next, prev, seek, like, volume, cover }
  state(): { playing, paused, title, artist, album, cover_url, progress, duration }
  command(name, args)
  events: started / stopped / track_changed / volume_changed
```

- **Арбитраж в прошивке** (уже есть `source_started`: кто начал, остальные на паузу), без сервера.
- Прошивка публикует одно JSON-состояние `media` (вместо `now_playing`, `airplay_now_playing`, `spotify_now_playing`, `bluetooth_status`) и принимает одну команду `media <source|auto> <command>`.
- Сервер (`media.py`) делает из этого `/api/v1/media`; панель, «Алиса, пауза», кнопки и Home Assistant используют только его.
- Источник — маленький адаптер (около 100 строк) в прошивке; новые (радио, Яндекс Музыка, плагины) подключаются тем же интерфейсом.
- Громкость: один ползунок (главная громкость), уже связан со Spotify и Bluetooth.

## 4. Плагины

### 4.1 Пакет и манифест
```json
{
  "id": "ru.example.presence",
  "name": "Присутствие",
  "version": "1.2.0",
  "author": "Имя",
  "icon": "icon.svg",
  "api": "1",
  "permissions": ["device.read", "events.subscribe", "home.control"],
  "entry": "main.py",
  "ui": { "utility": "page.html", "tile": "tile.html" },
  "update": { "url": "https://example.com/latest.json" }
}
```
Обязательные поля из вашего ТЗ: отображаемое имя, имя пакета (`id`), версия, автор, разрешения, иконка (по умолчанию стандартная).

### 4.2 Запуск и изоляция
- Плагин — **отдельный процесс** (Python), общается с сервером по локальному сокету JSON-RPC. Ключи и токены сервера плагину недоступны.
- Плагин получает собственный токен API с набором разрешений. Всё, что не разрешено, возвращает 403 и пишется в журнал.
- UI плагина: страница в «Утилитах» и/или плитка на главной, в `iframe` с ограниченным мостом postMessage (без доступа к токену панели).

### 4.3 Разрешения (первый список)
`media.read`, `media.control`, `device.read`, `device.control` (кольцо, экран, громкость), `voice.say`, `voice.listen`, `voice.intents` (свои команды), `scripts.run`, `home.read`, `home.control`, `alarms.manage`, `events.subscribe`, `network.<домен>` (исходящие запросы только к перечисленным доменам), `storage` (своя папка), `ui.utility`, `ui.tile`.
При установке пользователь видит список и подтверждает; опасные (`network.*`, `home.control`, `voice.listen`) выделяются.

### 4.4 Доверие и подпись
- **Подпись Ed25519**: разработчик подписывает пакет (хэш всех файлов плюс манифест). Публичный ключ разработчика лежит в **реестре разработчиков**, сам реестр подписан корневым ключом lostOS.
- Проверка при установке и при каждом обновлении. Подделать подпись без закрытого ключа разработчика нельзя. **Спрятать** ключ так, чтобы его нельзя было скопировать или реверснуть, невозможно, поэтому защита строится на подписи, а не на секретности.
- Не подтверждённый разработчик: предупреждение при установке, что lostOS не отвечает за утечку данных.
- Если плагин лезет за пределы разрешений (запрос без права): уведомление пользователю, счётчик нарушений, авто-отключение при повторе.
- Обновление: с сервера lostOS или сервера разрешённого разработчика (`update.url`). Если подпись новой версии не сходится, плагин **автоматически выключается**, приходит уведомление и предложение откатиться на предыдущую версию (прошлая версия хранится).

### 4.5 Системные плагины
Наши службы — те же плагины, но с флагом `system: true` (нельзя отключить или удалить; список можно свернуть или скрыть в «Настройки → Вид»):
`media` (MediaHub), `scenarios`, `smart-home`, `alarms`, `notifications`, `health`, `llm-gemini`, `alice-api` (озвучка и распознавание Алисы), `whisper`, `silero`.

### 4.6 LLM как плагин
Интерфейс «мозга»: `respond(text, context, tools) -> text | tool_calls`. Стоковый `llm-gemini` можно отключить, а `alice-api` отдаёт TTS и STT другим плагинам. Разработчик может выпустить свой «мозг» (ChatGPT, DeepSeek, локальная модель) тем же контрактом.

### 4.7 Список в «Настройки → Плагины»
Две группы: «Системные» (сворачиваемая) и «Мои». Карточка: иконка, имя, версия, автор, значок проверки, разрешения, включить, обновить, откатить, удалить.

## 5. Главная страница
Карточки — данные, а не разметка: `layout.json` (порядок, размер, источник данных). По умолчанию как сейчас (крупные информативные карточки). Раздел «Источники» переименовывается в «Пункт управления» (службы: AirPlay, Bluetooth, Spotify, ночной режим и т.д.). Плагины добавляют свои плитки через `ui.tile`; пользователь переставляет и скрывает их.

## 6. Что уже есть и пригодится
`scenarios.py` (сценарии с триггерами), `push.py` (уведомления), `update.py` (проверка версий), `certs.py`, `engines.py` (подключаемые движки голоса), `homeassistant.py`, громкость Spotify и Bluetooth, DLNA-плеер с обложками, `VERSION` и `CHANGELOG`.

## 8. Решения (приняты 2026-10-25)
1. **Плагины и память колонки.** Плагины исполняются на сервере, а не на колонке: на колонке они память не занимают. Замер сейчас (Мини 3, 244 МБ ОЗУ): `lostos` 30 МБ, librespot 19 МБ, shairport 15 МБ, свободно около 120 МБ. Для колонок старых поколений прошивку нужно ужимать: выключаемые модули (Zigbee, DLNA, Sendspin) при сборке, `-Os`, один общий JSON вместо набора датчиков. Язык плагинов: Python на сервере.
2. **Системные функции без сервера** (пауза, громкость, будильники, арбитраж источников) остаются в прошивке.
3. **Мультиплатформа.** Нужна поддержка всех поколений колонок. Прошивка уже знает `cucumber` (Миди), `plum` (Лайт 2), `bergamot` (Мини 3). Для остальных моделей нужно собрать список из вики hackalice.me (сайт сейчас отдаёт неверный сертификат, обходить его я не стал: пришлите текст или другое зеркало).
4. **Home Assistant без белого IP:** исходящее соединение из дома (агент «lostos-bridge» рядом с HA).
5. **Подпись плагинов:** Ed25519, реестр разработчиков, подмена невозможна без закрытого ключа разработчика.

## 9. Прогресс
- **C1 сделан (2026-10-25):**

Источники (AirPlay, Spotify, Bluetooth) только сообщают «играю / не играю»; последний начавший становится активным, остальным уходит пауза, при молчании пауза повторяется и затем источник считается остановленным.

Руководство: `docs/plugins.md`. Впереди: подписи Ed25519 и реестр (C4), песочница ОС, обновления и откат, вынос системных служб в плагины, свой интерфейс плагина.

## 10. Плагины как расширение прошивки, репозиторий и VDS (решения 2026-10-25)

### 10.1 Два уровня плагина в одном пакете
Один пакет `.lstplugin` (zip) может содержать обе части:
- **серверная часть** (`server/`, Python, уже работает): логика, сети, UI-данные (плитки), доступ к API сервера;
- **часть для колонки** (`device/plugin`): расширяет саму прошивку, то есть работает на колонке без сервера.

### 10.2 Плагины колонки: нативные, но в песочнице (решение пользователя: не WASM)
Часть для колонки это **статическая программа ARM** (любой язык, который собирается в статический armhf: C, Rust, Zig; проще всего `zig cc -target arm-linux-musleabihf -static`).
Прошивка запускает её отдельным процессом в песочнице (`satellite/src/plugins/sandbox.cpp`, проверено на колонке тестами `tests/sandbox_test.cpp`):
- **chroot** в папку плагина, где лежит только сама программа: нет ни `/dev`, ни `/proc`, ни других плагинов, ни прошивки;
- **свой пользователь** (uid 40001 и дальше), без привилегий, без групп, `no_new_privs`;
- **лимиты** (rlimit): память 48 МБ, время процессора, число файлов, один процесс, размер файла;
- **seccomp-фильтр**: любой системный вызов вне короткого списка убивает плагин (нельзя открыть файл, сокет, создать процесс или поток, смонтировать, ptrace);
- **единственный канал** к прошивке: дескриптор 3 (пара unix-сокетов). Всё, что плагин может сделать с колонкой (кольцо, часы, музыка, хранилище, события), идёт запросом, который прошивка проверяет по разрешениям (`plugins/host.cpp`).
Ядро колонки (4.9) не умеет пространства имён и memory-cgroup, поэтому память ограничена rlimit, а сети у плагина нет вообще (сокеты запрещены). Если плагину нужен интернет, это делается запросом через прошивку к домену из манифеста (ещё не сделано).
Нарушитель: плагин, убитый песочницей, перезапускается дважды и затем выключается; три запроса без разрешения тоже выключают его.

### 10.3 API
Единый `/api/v1` сервера (media, eq, lyrics, plugins, tiles, widgets, ...) расширяется разделами `device` (LED, часы, кнопки), `voice` (say, интенты), `scripts`, `alarms`, `home`.
К серверному API ходит и панель, и плагины (через брокер с разрешениями), и боты. Команды и события колонки остаются одним протоколом (`media ...`, `eq ...`, датчики).

### 10.4 Пакет и установка
`.lstplugin` = zip: `manifest.json`, `server/…`, `device/plugin` (статическая программа ARM, необязательно), `icon.svg`, `signature.json` (потом). Установка сейчас **вручную**: «Настройки → Плагины → Установить из файла»
(проверка манифеста, защита от `..` и больших файлов, плагин остаётся выключенным до подтверждения прав). Дальше: установка по ссылке/из репозитория.

### 10.5 Официальный репозиторий (можно поднять отдельно)
Статический каталог: `index.json` (список: id, версии, URL пакета, SHA-256, подпись, разрешения, описание) + файлы `.lostos`. Размещается на любом статическом хостинге или на нашем VDS;
в панели адрес репозитория настраивается (по умолчанию официальный, можно добавить свой). Подпись Ed25519 по хэшу пакета, ключи разработчиков в `developers.json`, подписанном ключом lostOS.
Серверный кусок репозитория (приём пакетов, проверка, публикация) отдельный маленький сервис, который можно запустить где угодно.

### 10.6 VDS (один сервер)
На нём: **lostOS Server** (панель и API по HTTPS, вход через Telegram), **Telegram-бот для пользователей** (уведомления о событиях колонки, вход, управление: пауза, громкость, сценарии, список сессий), **бот ченджлогов**
(следит за релизами/коммитами на GitHub и пишет в канал; вебхук GitHub, текст из `CHANGELOG.md`) и репозиторий плагинов (статика). Связь с колонкой и Home Assistant дома через исходящий туннель «lostos-bridge».
Общий порядок: VDS и боты готовим, когда будет сервер; GitHub и публикация в самом конце.

## 11. Свобода действий плагинов под разрешениями (решение 2026-10-25)
Принцип: плагин может почти всё, но **только через прошивку или сервер и только с разрешением**, а секреты и системные файлы ему недоступны вообще.

### 11.1 Уровни разрешений
| Уровень | Примеры | Как показывается |
|---|---|---|
| обычные | `ui.tile`, `storage`, `events.subscribe`, `media.read`, `device.read` | в списке прав |
| чувствительные | `media.control`, `device.led`, `device.display`, `events.publish` | выделены |
| опасные | `network.connect`, `network.listen`, `audio.play`, (планируются) `assistant.intercept`, `brain.replace`, `audio.capture` | красное предупреждение при включении |
Не подтверждённый разработчик: отдельное предупреждение, что lostOS не отвечает за утечку данных.

### 11.2 Сеть (сделано на колонке)
Сокеты в песочнице создавать нельзя вообще (seccomp). Плагин с `network.connect` просит прошивку `connect <хост> <порт>` и **получает готовый открытый сокет** (передача дескриптора), с `network.listen`
получает слушающий TCP-сокет (порт от 1024) или UDP-сокет с multicast (mDNS, SSDP). Прошивка отказывает в адресах самой колонки (loopback, её собственные адреса: adb, API, соседние плагины) и в служебных портах.
Так на колонке можно сделать приёмник Chromecast или Telegram-клиент без доступа к `adb`. Домены по списку и HTTPS-посредник (`http.get/post` к разрешённым доменам без TLS в плагине) впереди.

### 11.3 Звук (сделано на колонке)
`audio.play`: плагин получает канал для звука 48 кГц стерео S16, прошивка играет его через общий микшер (с эквалайзером) как **источник музыки** медиа-хаба
(остальные источники встают на паузу, как между AirPlay и Spotify). Так можно сделать Chromecast или любой «приёмник». Запись с микрофона (`audio.capture`) отдельное опасное разрешение, пока не делаем.

### 11.4 Секреты и системные файлы
- **Плагин колонки** сидит в chroot своей папки: он не видит `/data/lostos/api_key`, `.env`, ключи Wi-Fi, `/etc`, `/proc`, `/dev`, чужие плагины. Прочитать их технически нечем (нет `open`).
- **Серверная часть плагина** (Python) сейчас обычный процесс компьютера и **может читать файлы сервера**, в том числе `.env` с ключами. Честно: на Windows надёжной песочницы для Python-процесса мы не строим.
  План: серверные плагины работают на **VDS (Linux)** в отдельном пользователе и в изоляции (`bubblewrap` или systemd-sandbox: только своя папка, нет доступа к конфигам сервера), а секреты сервера лежат в каталоге, закрытом для этого пользователя. До этого серверные части ставим только свои и из доверенных источников
  (в панели плагины без подписи помечены «разработчик не подтверждён»). Плагины, которым нужны только колонка и API, можно делать только на стороне колонки: их песочница уже настоящая.

### 11.5 Перехват Алисы и замена мозга (сделано на сервере)
- `assistant.intercept` (опасное): плагин получает каждую услышанную фразу (`assistant.heard`: текст и имя говорящего) раньше штатного ассистента и может **забрать** её ответом `{"claim": true, "reply": "..."}`; сказанное `reply` озвучивается обычным голосом, Gemini не вызывается. Не ответил за 2,5 с или не забрал: фраза идёт дальше. При записи голоса (обучение) фразы не перехватываются.
- `brain.replace` (опасное): плагин **полностью заменяет нейросеть**. Сервер спрашивает `brain.respond` и отдаёт текст, заметку о контексте (кто говорит, перебили ли), системный промпт (персона, контекст, умный дом), историю разговора и описания всех команд в обычной JSON-схеме. Плагин сам ходит к своей модели (ChatGPT, DeepSeek, локальная) и может вызывать команды через `tools.list` / `tools.call` (музыка, таймеры, будильники, сценарии, дом, поиск, погода). Закрыты внутренние команды с `_` и всё, чего нет у штатного ассистента; ограничения штатного ассистента (незнакомый голос, время в таймере) действуют и для плагина, так как команды идут через тот же `run_tool`.
  Ответ плагина обрабатывается как ответ Gemini: можно вернуть `[Smiley]` и т. п. для эмоции и `[IGNORE]`, если фраза не к ней. Ошибка, тишина дольше 40 с или пустой ответ: тихо отвечает штатный мозг, а пользователю приходит уведомление.
- **Хаб команд** (`assistant.tools`, опасное): плагин сам добавляет команды ассистенту (`tools.register`: имя, описание, JSON-схема параметров, `restricted` для команд, закрытых незнакомому голосу). Команда видна **всем мозгам одинаково**: встроенному Gemini (схема переводится в его формат) и мозгам-плагинам (`tools.list`). Вызов идёт через общий `run_tool`: сервер спрашивает плагин `tool.call` и отдаёт результат текстом модели. Имена встроенных команд занять нельзя, от одного плагина до 16 команд; команды уходят вместе с плагином.
- **Речь** (`speech.stt`, `speech.tts`, опасные): плагин может быть распознавателем (`stt.transcribe`: PCM 16 кГц в base64, ответ `{"text"}`) и голосом (`tts.synthesize`: ответ `{"wav_b64"}` или `{"pcm_b64","rate"}`, сервер сам приводит к 48 кГц). Выбирается в панели: Настройки, движки (рядом с Яндексом, Whisper, Алисой и Silero). Если плагин молчит, падает или остановлен, сразу работает облако Яндекса, пользователю приходит уведомление.
- Остаётся: нажатие кнопки и слово активации на самой колонке (прошивка отдаёт плагину `wake`/`button` с правом забрать их), `audio.capture` для плагина, который слушает микрофон сам.
