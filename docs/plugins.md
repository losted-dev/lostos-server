# Плагины lostOS: как написать свой (версия API 1)

Плагин это папка с манифестом и скриптом на Python. Сервер запускает его **отдельным процессом** и отвечает на его запросы
только в пределах разрешений, которые дал пользователь.

```
server/plugins/system/<id>/     встроенные плагины (всегда включены, нельзя отключить)
server/plugins/user/<id>/       установленные пользователем (по умолчанию выключены)
```

## Пакет и установка вручную
Пакет это zip с расширением **`.lstplugin`**: в корне (или в одной внешней папке) лежат `manifest.json`, скрипт и всё остальное. «Настройки → Плагины → Установить из файла»
(или `POST /api/v1/plugins/install` с содержимым файла) проверяет пакет (размер до 6 МБ, до 24 МБ после распаковки, пути без `..`, манифест), кладёт его в
`plugins/user/<id>/` и **оставляет выключенным**: включает пользователь после просмотра разрешений. Повторная установка с тем же `id` обновляет плагин (его данные
остаются, он снова выключен). «Удалить» (или `DELETE /api/v1/plugins/<id>`) убирает плагин и его данные.

## manifest.json
```json
{
  "id": "ru.example.stats",
  "name": "Треки за сегодня",
  "version": "1.0.0",
  "author": "Имя",
  "api": "1",
  "icon": "chart",
  "description": "Считает треки за день",
  "permissions": ["media.read", "events.subscribe", "storage", "ui.tile"],
  "entry": "main.py"
}
```
`id` как `ru.example.name` (латиница, цифры, точки и дефисы), `version` как `1.0.0`. Иконки: `sun cloud music chart bolt bell home star clock note`.
Если манифест неверный, плагин не загружается, причина видна в «Настройки → Плагины» и в `GET /api/v1/plugins` (`bad`).

## Разрешения
| Разрешение | Что даёт |
|---|---|
| `media.read` | `media.state`: что играет (источник, название, исполнитель, обложка, позиция) |
| `media.control` | `media.command`: play, pause, next, previous, volume (осторожно: управляет музыкой) |
| `device.read` | `device.volume`: громкость колонки |
| `events.subscribe` | события `media` (смена трека, пауза) |
| `storage` | `storage.get/set`: свои данные (до 200 КБ, файл `data/storage.json` в папке плагина) |
| `ui.tile` | `tile.set`: плитка в разделе «Сейчас» на главной |
| `weather.read` | `weather.get`: погода |

Запрос без разрешения возвращает ошибку и считается нарушением. Три нарушения: плагин выключается, пользователь получает уведомление.

## SDK (`server/lostos_sdk.py`, только стандартная библиотека)
```python
from lostos_sdk import call, on, run

@on("media")                         # приходит при смене трека (нужны events.subscribe и media.read)
def changed(now):
    call("tile.set", title="Играет", value=now.get("title", "")[:12], subtitle=now.get("artist", ""), icon="music", accent="#8b5cf6")

call("events.subscribe")
run()                                # держит плагин живым и доставляет события
```
`call(method, **params)` возвращает результат или бросает `PluginError`. Полный пример: `plugins/user/ru.lostos.music-stats/`.

## Плитки (виджеты «Сейчас»)
`tile.set` принимает `title`, `value` (крупный текст до 20 знаков), `subtitle`, `icon`, `accent` (цвет `#rrggbb`). Плитка рисуется панелью сама, плагин не
вставляет в панель код. Штатная плитка «Погода» работает так же (включается в «Настройки → Плагины → Штатные виджеты»).

## Что пока не сделано (честно)
- Плагин это обычный процесс компьютера: разрешения ограничивают то, что **сервер** делает для него, но не мешают самому процессу открыть сокет или файл.
  Песочница на уровне ОС, подписи разработчиков (Ed25519), реестр, обновления и откат описаны в `docs/lostos-architecture.md` (4.4) и впереди.
- Вкладка плагина в «Утилитах» и свой интерфейс (кроме плиток) тоже впереди.

# Плагин для колонки (нативная программа в песочнице)

Плагин может иметь часть, которая работает **на самой колонке**, без сервера. Она описана в манифесте:
```json
"device": {"binary": "device/plugin", "permissions": ["events.subscribe", "device.led", "device.display"]}
```
Файл `device/plugin` в пакете это статическая программа ARM (armhf). Сервер при включении плагина просит колонку скачать её (по http из этого сервера, с проверкой SHA-256),
колонка запускает программу в песочнице. Что видит и может программа, описано в `docs/lostos-architecture.md` (10.2).

## Сборка
```
zig cc -target arm-linux-musleabihf -static -Os main.c -o device/plugin
```
Пакет: zip с `manifest.json`, `main.py` (серверная часть, может быть пустой) и `device/plugin`, расширение `.lstplugin` (скрипт: `ref/build-example-plugin.sh`).
Пример: `satellite/examples/button-flash/` (по центральной кнопке кольцо вспыхивает фиолетовым, на часах HI).

## SDK на C (`satellite/sdk/lostos_plugin.h`, один заголовок)
```c
#include "lostos_plugin.h"
int main(void) {
  char ev[128], res[64];
  lp_call("subscribe", "button", res, sizeof res);           // нужно events.subscribe
  for (;;) {
    int n = lp_wait_event(ev, sizeof ev, 10000);              // события: "button action", "media spotify 1 Название", "volume 0.50"
    if (n < 0) return 0;                                      // прошивка закрыла связь: плагин останавливают
    if (n > 0 && !strncmp(ev, "button action", 13)) lp_call("led", "139 92 246 2", res, sizeof res);   // нужно device.led
  }
}
```
Протокол: одна строка на сообщение. Запрос `<n> <метод> <аргументы>`, ответ `<n> ok <результат>` или `<n> err <причина>`, события `! <имя> <данные>`.

| Метод | Разрешение | Что делает |
|---|---|---|
| `log <текст>` | нет | строка в лог колонки |
| `subscribe button\|media\|volume` | `events.subscribe` | подписка на события |
| `led <r> <g> <b> <сек>` | `device.led` | кольцо показывает цвет (1–30 с) |
| `display <сек> <текст>` | `device.display` | часы показывают текст (до 12 знаков) |
| `media play\|pause\|playpause\|next\|previous` | `media.control` | управление музыкой |
| `volume` | `device.read` | громкость 0..1 |
| `get <ключ>` / `set <ключ> <значение>` | `storage` | свои данные (до 32 ключей, до 256 знаков) |
| `publish <тема> <текст>` | `events.publish` | событие колонки для Home Assistant |
| `resolve <имя>` | `network.connect` | IPv4-адрес по имени |
| `connect <хост> <порт>` | `network.connect` | TCP-подключение: прошивка открывает сокет и **передаёт дескриптор** (`lp_call_fd`); адреса самой колонки запрещены |
| `listen <порт>` | `network.listen` | слушающий TCP-сокет (порт от 1024), передаётся дескриптором |
| `udp <порт> [группа]` | `network.listen` | UDP-сокет, при желании в multicast-группе (mDNS/SSDP), передаётся дескриптором |
| `audio.open` / `audio.close` | `audio.play` | канал для звука (48 кГц, стерео, S16LE): `lp_call_fd("audio.open", ...)` возвращает pipe, пишите в него PCM; плагин становится источником музыки колонки |
| `button claim` / `button release` | `assistant.intercept` | забрать центральную кнопку (кнопку Алисы): пока плагин работает, нажатие само ничего не делает (не вызывает ассистента, не ставит паузу, не включает Spotify двойным), плагин получает событие `button action` и решает сам. Остановка звонящего таймера и отмена диалога работают. Кнопка возвращается при остановке, выключении или удалении плагина |

Сокеты создать самому нельзя (песочница убивает плагин): только получить у прошивки. Тестовый плагин `tests/plugin_net.c` проверил: подключение к loopback и к своему адресу отклонено, к серверу прошло, тон 440 Гц играется, `socket()` убивает плагин.

Кнопки: события кнопок это **копии**: центральная кнопка по-прежнему запускает Алису, плагин лишь узнаёт о нажатии. (Перехват кнопки плагином позже, с отдельным разрешением.)

## Проверено на колонке
Пример и три враждебных плагина (запрос без разрешения: выключен после третьего; запрещённый системный вызов: убит песочницей, перезапущен дважды, затем выключен).

## Перехват фраз и замена мозга (серверные плагины)
Оба права опасные, панель показывает красное предупреждение при включении.

| Право | Вопрос от сервера | Ответ плагина |
|---|---|---|
| `assistant.intercept` | `assistant.heard` `{text, who}` | `{"claim": true, "reply": "что сказать"}` или `{"claim": false}` |
| `brain.replace` | `brain.respond` `{text, note, who, system, history, tools}` | строка с ответом (или `{"reply": "..."}`) |

Для мозга ещё два метода плагина к серверу (нужно `brain.replace`): `tools.list` (команды ассистента) и `tools.call` `{name, args}` (выполнить команду, результат строкой для модели). Обычный `run_tool` ограничения штатного ассистента не снимает.

С SDK это пара обработчиков:

```python
from lostos_sdk import call, handle, run

@handle("assistant.heard")
def heard(p):
    return {"claim": p["text"].lower().startswith("тест"), "reply": "Это ответил плагин."}

@handle("brain.respond")
def think(p):
    ...   # спросить свою модель, при вызове функции: call("tools.call", name="get_weather", args={})
    return "Ответ"

run()
```
Пример: `server/plugins/user/ru.lostos.test-brain`, проверка без колонки: `python server/tests_brain.py`.

## Команды, распознавание и озвучка от плагинов
| Право | Что делает плагин | Вопрос сервера → ответ |
|---|---|---|
| `assistant.tools` | `call("tools.register", name, description, parameters, restricted=False)` при старте | `tool.call` `{name, args}` → строка с результатом для модели |
| `speech.stt` | становится выбором в «Движках» | `stt.transcribe` `{pcm_b64, rate: 16000, language}` → `{"text": "..."}` (пустой текст: ничего не слышно) |
| `speech.tts` | то же | `tts.synthesize` `{text, rate}` → `{"wav_b64": ...}` или `{"pcm_b64": ..., "rate": 24000}` (16 бит, моно) |

Имя команды: `[a-z][a-z0-9_]{2,40}`, не совпадает со встроенными и чужими; описание обязательно (по нему модель решает, когда вызывать); `parameters`: JSON-схема до 4 КБ. Команда видна всем мозгам: Gemini и плагинам с `brain.replace` (`tools.list`). Описания команд попадают в запрос к модели, поэтому право опасное: плагин с чужими описаниями может пытаться ею управлять.

Пример: `server/plugins/user/ru.lostos.test-speech` (команда `coin_flip`, озвучка писком по сигналу на слово, «распознавание» одной фразы). Автопроверка: `python server/tests_brain.py`.

## Страница плагина, README и логотип
В панели (Настройки → Плагины) нажмите на плагин: откроется его страница. Сверху название, логотип, автор, версия и бейджи (работает, разработчик не подтверждён), источник установки (ручная загрузка с именем файла и SHA-256, репозиторий, встроенный пакет). Ниже разрешения с пояснениями простым языком: что получит плагин, чем это рискованно, степень (безопасное, управляет колонкой, опасное), выдано оно или спросим при включении. Внизу описание из README, переключатель и «Удалить».

В манифесте два необязательных поля:
- `"logo": "logo.png"`: картинка плагина (png, jpg, webp, до 300 КБ; файл проверяется по первым байтам, а не по имени). SVG не принимается.
- `"readme": "README.md"`: файл описания (по умолчанию `README.md`, до 100 КБ).

Что понимает README: заголовки, абзацы, **жирный**, *курсив*, ~~зачёркнутый~~, `код` и блоки кода, списки (в том числе вложенные и с галочками), цитаты, таблицы, линия, ссылки и картинки.

Как защищена страница (тексту плагина не доверяем):
- README рисует `web/md.js`, он не строит HTML из текста: каждый элемент создаётся через DOM, текст вставляется как текст. Теги `<script>`, `<img onerror>`, `<iframe>`, `<svg>` и любой другой HTML показываются буквами, а не выполняются.
- Ссылки только `http(s)` и `mailto`; из адреса убираются невидимые символы и пробелы (обход вроде `java<таб>script:`), `javascript:`, `data:`, `vbscript:`, `file:` и относительные адреса становятся простым текстом. Открываются в новой вкладке с `noopener noreferrer nofollow`, настоящий адрес виден в подсказке.
- Картинки только из самой папки плагина (png, jpg, webp, gif), без `..`, `%`, `?`, без `data/`. Внешние картинки не загружаются (иначе их владелец узнал бы, что вы открыли страницу), вместо них показывается описание.
- Картинки отдаёт сервер (`/plugins-asset/<id>/…`) только как картинки: тип по расширению после проверки первых байтов, `nosniff` и `Content-Security-Policy: sandbox`; `.svg`, `.html`, `data/` и всё вне папки плагина дают 404.
- Пакет `.lstplugin` не принимается, если в нём путь с `..`, `:` (в том числе потоки NTFS `a.txt:x`), управляющие символы, имена вроде `CON`/`AUX` или имена, оканчивающиеся точкой/пробелом.
- Ограничения на размер, число блоков, вложенность и длину форматируемого текста: страница из мусорного README не подвешивает панель (проверено на 100 000 звёздочек, вложенных цитатах, таблицах на 5 000 строк и т. п., каждый случай быстрее 30 мс).
- Остаётся: общей политики безопасности (CSP) для самой панели пока нет.



## Кнопка Алисы
- Переключатель `alice_button` не для пользователя, а внутренний (в панели его нет): им управляют плагины, сценарии и Home Assistant («Centre button starts the assistant», категория настроек), в панели его можно поменять запросом `POST /api/do {"a":"switch","id":"alice_button","on":false}`; хранится в `state.conf` колонки. Выключен: центральная кнопка не вызывает ассистента, остальное (пауза музыки, двойное нажатие на Spotify, остановка таймера) остаётся.
- Плагин с правом `assistant.intercept` может забрать кнопку целиком (`button claim`), когда ему нужно своё поведение. Пример: `tests/plugin_claim.c`, пакет `dist/build/test-plugins/ru.lostos.test-claim.lstplugin`.
- Слово активации «Алиса» этими настройками не отключается (его слышит прошивка); для голоса есть `assistant.intercept` на сервере (раздел «Перехват фраз»).

## Системные плагины колонки (AirPlay 2, Spotify Connect)
Приёмники колонки не отдельная «обвязка», а плагины системы («Встроенный пакет»): `ru.lostos.airplay`, `ru.lostos.spotify`. Они лежат так же, как остальные, в `/data/lostos/plugins/<id>/`, с `plugin.conf`, но с `kind=system`: работают вне песочницы (это сами приёмники колонки), поэтому их программы (shairport-sync, nqptp, avahi, librespot, библиотеки) идут пакетом рядом с `plugin.conf`.
- Код, который их настраивает и запускает, часть lostos: `src/plugins/system.{h,cpp}` (запуск, присмотр, перезапуск с паузой, подхват уже работающих процессов после обновления lostos, без обрыва музыки) и `src/plugins/system_drivers.cpp` (конфигурация, `.asoundrc`, avahi, эквалайзер). `airplay.sh`, `S99zairplay` и скрипт события librespot больше не нужны: событие librespot обрабатывает сам `lostos --spotify-event`.
- Включение: `enabled=0/1` в `plugin.conf` (так хранит выбор владельца сама колонка, он переживает перезагрузку). Выключенный плагин не запускается и не включается сам: ни переключением микрофона, ни голосом («включи AirPlay» ответит, что он выключен в плагинах), ни после сброса сессии; включает его только переключатель владельца. При выключении Spotify колонка забывает, что он играл; команды те же, что у остальных плагинов (`enable <id>`, `disable <id>`), в списке плагинов они стоят вместе с остальными.
- Звук системы («audio»: эквалайзер поверх `/etc/asound.conf` и процесс, который держит микшер) не плагин, а часть самой системы; запускается раньше всего, до первого обращения lostos к ALSA.
- Проверка и управление на колонке: `/data/lostos/lostos --system status` (также `start|stop|restart|enable|disable <id>`); журналы программ в `/tmp/lostos-system/<программа>.log`.
- Перенос колонки со старой раскладкой (`/data/shairport`, `/data/librespot`): `tools/migrate-system-plugins.sh`.
- Имя колонки для AirPlay и Spotify: модель («Я.Станция Мини 3»), либо строка из `/data/lostos/speaker-name`.
- Не сделано: страницы этих плагинов в панели (логотип, README, переключатель) и упаковка плагинов в установщик.

## Системные плагины на сервере и свой мозг
Всё, что lostOS делает сам, тоже плагины («Встроенный пакет», папка `server/plugins/system/<id>/` с `manifest.json`, `README.md`, `logo.png`). Их нельзя удалить; выключить можно только те, у кого в манифесте `"switchable": true`.

| Плагин | Что это | Переключатель |
|---|---|---|
| `ru.lostos.llm` «Мозг lostOS» | штатная нейросеть (Gemini или Claude по ключу владельца) | есть |
| `ru.lostos.alice-api` «Alice API» | голос и слух Алисы в облаке Яндекса: озвучка и распознавание | есть |
| `ru.lostos.airplay`, `ru.lostos.spotify` | приёмники на самой колонке (раздел «Системные плагины колонки») | есть, на странице плагина (вместе с переключателем уходит и плашка с главной) |

В манифесте встроенного пакета: `builtin` (`llm`, `alice-api` или `speaker`: что именно он представляет, программы у пакета нет), `switchable`, `requires` (id плагинов, которыми он пользуется; панель показывает «Использует» и «Им пользуется»), `side` (`server` или `speaker`). Во внешнем пакете эти поля не принимаются.

**Мозг выключен.** Вопросы к Gemini и Claude (в том числе перевод поискового запроса) не уходят. Если нет и другого мозга (`brain.replace`), ассистент отвечает «Мозг ассистента выключен». Если выключить штатный мозг и включить чужой, думает чужой. Если чужой мозг отвечает ошибкой, а штатный включён, ответит штатный.

**Alice API выключен.** Облачные озвучка и распознавание не вызываются ни штатным мозгом, ни плагинами. Остаются Silero и Whisper (если установлены) и плагины с `speech.tts` и `speech.stt`.

### Чужой мозг, голос и слух
Разработчик выпускает обычный плагин; от штатного мозга его отличает только то, что он выбран и получает вопросы:
- `brain.replace`: думает вместо штатного мозга (фраза, история, дом и команды приходят в `brain.respond`, см. выше).
- `speech.stt` и `speech.tts`: свои распознавание и озвучка; появляются в «Распознавание и озвучка».
- `assistant.tools`: свои команды, их видят все мозги.
- `alice.api` («Голос и слух Алисы»): плагин может сам воспользоваться голосом и слухом Алисы через Alice API:

| Метод плагина к серверу | Что передать | Результат |
|---|---|---|
| `alice.tts` | `{"text": "..."}` до 1000 знаков | `{"pcm_b64", "rate"}` (16 бит, моно) |
| `alice.stt` | `{"pcm_b64"}` 16 кГц, 16 бит, моно, 0,1–30 с | `{"text"}` |

Владелец может выключить Alice API в любой момент: тогда методы отвечают ошибкой «alice-api выключен владельцем» (в SDK это `PluginError`), и плагин должен её перехватить и ответить иначе, например текстом, а не падать. Права опасные: тексты и записи голоса уходят в облако Яндекса. Автопроверка: `python server/tests_system.py`.

## Плашки главной страницы принадлежат плагинам
Плашка не нарисована в интерфейсе, её приносит плагин. Включён плагин, плашка есть; выключен или удалён, плашки нет, и страница выглядит так, будто его никогда не было.
- Плагин на сервере с правом `ui.tile` показывает плашку на полке «Сейчас» вызовом `tile.set` (`title`, `value`, `subtitle`, `icon`, `accent`).
- Встроенный пакет описывает плашку в манифесте: `"tile": {"shelf": "now|sources", "title": "AirPlay", "icon": "airplay", "tint": "air"}`. Живая строка под названием приходит с состоянием панели (`tile_status`). У AirPlay 2 и Spotify Connect плашки на полке «Источники».
- Нажатие на плашку открывает страницу её плагина. Погода ― штатный виджет `lostos`, выключается в «Плагины».

**Режим изменения**, как у виджетов iOS: кнопка «Изменить» в самом низу главной страницы или удержание плашки (около 0,4 с). Свайп по плашке только прокручивает страницу или полку: плашка берётся только удержанием, тогда она подсвечивается и приподнимается. Плашки трясутся, у каждой значок «−» (убрать с главной, вернуть можно здесь же значком «+»), под ней подпись, чей это виджет; плашки двигаются перетаскиванием вдоль полки. То же умеют делать штатные части главной (плеер, будильник, Bluetooth и «Что она слышала»): это плашки владельца `lostos`, их нельзя удалить, только убрать и переставить. Нажатие на погоду и на штатные плашки ничего не открывает. Если плагин, у которого была плашка, сейчас выключен или удалён, на её месте пунктирная заглушка «Виджет плагина «AirPlay 2» · плагин отключён» (или «плагин удалён»); значок «×» убирает заглушку насовсем. Порядок и спрятанные плашки хранит сервер (`home_tiles.json`), модуль `server/tiles.py`, ручки `GET /api/v1/tiles`, `POST /api/v1/tiles/layout`, `DELETE /api/v1/tiles/<id>`. Проверка: `python server/tests_system.py`.

## Системные виджеты и погода (2026-10-26)
- **Не включены по умолчанию** (владелец включает их в режиме «Изменить» значком «+»): «Процессор» (нагрузка и температура), «Память» (занято и всего) и «Свободно» (место на `/data`). Цифры берутся с самой колонки: lostos раз в 5 секунд отправляет текстовый датчик `system_stats` (`cpu=…;temp=…;mem_used=…;mem_total=…;disk_free=…;disk_total=…`, объёмы в килобайтах), сервер показывает их плашками, пока колонка на связи. Любой плашке сервер может поставить `off_by_default`: она появляется выключенной один раз, дальше решает владелец.
- **Погода** рисуется по прогнозу Open-Meteo без ключа (город из `WEATHER_CITY`, при нужде точные `WEATHER_LAT` и `WEATHER_LON`): город, температура, знак погоды и три ближайшие части суток (ночь, утро, день, вечер). Фон живёт вместе с погодой (`web/weather_fx.js`): ясный день с сиянием солнца, звёздная ночь, плывущие облака, косой дождь, гроза со вспышками, снег, туман. Если прогноз недоступен, остаётся обычная плашка с погодой Яндекса. Посмотреть любую погоду без ожидания: `/?wx=storm-night` (`clear partly cloud fog rain snow storm`, `-day` или `-night`).
- **Страница системного плагина** больше не показывает список разрешений: они у него всё равно все.
- **Консоль** (Утилиты, «Для своих»): `say <фраза>` (ассистенту текстом), `tools`, `tool <имя> {json}`, `speaker <команда>` (строка команды самой колонке, например `speaker plugin list`) и `sh <команда>` (оболочка компьютера сервера). Оболочка выключена, включается переключателем на странице и только на сервере со входом (VDS) или с самого компьютера сервера: на открытом всем в сети сервере без входа она недоступна. Команды пишутся в журнал сервера (`console: …`).

## Галерея виджетов, «Железо», подписи и минимальная версия (2026-10-26)
- **Галерея виджетов** (кнопка «+» на главной, окно «Виджеты»): все плашки как у iOS, превью живое. Два раздела: «Информативные виджеты» и «Пункт управления» (плашки полки «Источники»). Каждой плашке подписано, что она показывает, и стоит «Добавить» или «На главной ✓». Есть поиск. Плашки отключённых плагинов в галерее не видны. Данные для неё отдаёт `GET /api/v1/tiles` (поля `label`, `about`, `group` = `info|control`); у плагина они берутся из его манифеста (`tile.title` и `description`).
- **Подпись под каждым виджетом** (`label`): «Плеер», «Будильник», «Погода», «Процессор», «Память», «Накопитель», «Железо». Знак L с плашки погоды убран, значок погоды вмещается в плашку.
- **Виджет «Железо»** (`sys.hw`, не включён по умолчанию): процессор, температура, память и накопитель одной плашкой. Появляется, когда колонка прислала все цифры `system_stats`.
- **Минимальная прошивка плагина**: в манифесте `"min_firmware": "0.3.0"` (версия lostOS на колонке, формат `0.3` или `0.3.0`). Если на колонке версия ниже, сервер отвечает на включение плагина `409` с текстом «Нужна прошивка lostOS … или новее», а на странице плагина видна строка «Нужна прошивка lostOS». Пока версия колонки не известна (колонка не на связи), плагин не блокируется. Все штатные плагины пакета требуют `0.3.0`.
- **Об этом устройстве** (Настройки): имя колонки (его видят AirPlay и Spotify), без кнопок: имя сохраняется, когда поле закрыто (Готово или тап мимо), пустое поле значит имя модели. Ниже модель («Станция Мини 3»; тап по тексту показывает кодовое имя `bergamot`, `cucumber`, `plum`…), версия lostOS (только число, `0.3.0`), прошивка колонки (`/system/vendor/quasar/version_full`), чип («Amlogic AXG · 4× Cortex-A53», lostos читает его из device tree и `/proc/cpuinfo`), память и накопитель как «занято / всего МБ». Всё приходит текстовым датчиком `system_stats` раз в 5 секунд.
- **Переименование колонки**: `POST /api/v1/speaker {"name": "Кухня"}` (до 40 знаков, пустое имя ― вернуть имя модели). Сервер шлёт колонке команду `name <имя>`; lostos сохраняет имя в `/data/lostos/speaker-name`, перезапускает AirPlay 2 и Spotify Connect, и они появляются в списках под новым именем. Проверено на Мини 3: файл, `shairport.conf` (`name =`), `librespot --name`.

- **Главная по умолчанию**: «Сейчас» ― плеер, будильник, погода; «Пункт управления» ― AirPlay, Bluetooth, Spotify. Всё остальное (процессор, память, накопитель, «Железо», «Что она слышала») лежит в галерее и добавляется только кнопкой «Виджеты»: убранная плашка в режиме «Изменить» больше не показывается с «+». Подписи под плашками видны только в режиме «Изменить». Режим «Изменить» выключается тапом по пустому месту главной и сменой вкладки.

## Виджет «Часы» (2026-10-26): настоящее зеркало дисплея
Штатный виджет галереи (выключен по умолчанию, включается в «Изменить» на главной, группа «Информация»): карточка одного тона без подписи, по центру семисегментный циферблат. Это **полное зеркало** дисплея колонки, а не свои часы:
- **Прошивка** (`hw/clock.cpp`, `Clock::publish_frame`): после каждого обновления дисплея собирает то, что реально записано в светодиоды (яркость каждого сегмента 0..f у 4 цифр по a..g, потом двоеточие и светодиод градуса или будильника: 30 шестнадцатеричных знаков) и публикует текстовым сенсором `display_frame` (ключ 52, скрыт в Home Assistant), не чаще примерно 14 раз в секунду и только при изменении. Поэтому в зеркале видно всё, что показывает колонка: время, текст (погода, будильник), таймер, громкость, дыхание и бегущий блик при ответе ассистента, глаза, эквалайзер, смену трека.
- **Сервер:** `DISPLAY` в `voice_server.py` хранит последний кадр, `GET /api/v1/display` отдаёт `{"f": кадр, "age": секунд с изменения, "on": колонка на связи}`.
- **Панель:** опрашивает `/api/v1/display` 4 раза в секунду, пока виджет на экране и вкладка открыта, и ставит прозрачность каждому сегменту по его яркости. Если прошивка старая (сенсора нет), рисует время или текст сервера (двоеточие ровное, как у самой колонки).
Объёмная модель колонки была сделана и убрана по решению пользователя в тот же день.

## Проверка подписи на самой колонке (2026-10-27)

Сервер говорит колонке, какой плагин скачать и какие права ему дать (`plugin install <id> <url> <sha256> <права> <база>`). Чужому серверу этого решать нельзя, поэтому колонка проверяет подпись пакета **сама** (`plugins/trust.cpp` в прошивке):
- Вместе с программой она скачивает `lostos-signature.json`, `manifest.json` и подписанный список разработчиков (`developers.json` и `.sig`, сервер лишь передаёт их).
- Из таблицы `files` в подписи она пересчитывает дайджест, проверяет подпись Ed25519 и что скачанные программа и манифест именно те, что подписаны.
- Ключ доверенный, если это ключ команды (зашит в прошивку) или разработчик из списка `plugapi`, подпись которого колонка проверяет зашитым в неё ключом списка, не отозванный и в срок.
- Доверенный пакет получает права, которые объявляет его подписанный манифест (`device.permissions`) и которые просит сервер. Любая другая программа получает только безобидные права: опасные (`network.connect`, `network.listen`, `audio.play`, `assistant.intercept`, `events.publish`) отказаны, что бы ни просил сервер. Вердикт сохраняется на колонке и применяется при каждом включении; ключи списка меняются только новой прошивкой.
- Кнопка Алисы для этого не нужна. Плагин без подписи работает, но без опасных прав. Проверено на эмуляторе (`ref/e2e_device_trust.py`).
